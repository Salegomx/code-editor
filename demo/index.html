<code-editor>

A code editor for web pages. It edits code the way an IDE does, sends its code with a form just like a <textarea>, and shows read-only code samples in documentation. Everything on this page is live: click into any example and try it.

Getting started

  1. Load the script once on the page. It can go anywhere, and if the tag ends up on the page more than once (one per editor, for example), the browser still loads the file only once.
  2. Add a <code-editor> and put the code between its tags.

That's all it takes. The editor highlights the code, removes the indentation that came from the surrounding HTML, and is ready to edit. Inside a form it's sent like any other field once you give it a name; see Forms.

Attributes

All attributes are optional.

Attribute Values Default What it does
name any text none The field name the form sends the code under, like name on an <input>. Forms
id any text none A normal HTML id. When there's no name, the form uses the id as the field name.
language json, javascript, typescript, jsx, tsx, html, css, xml, shell, text text Syntax highlighting, and how minify treats the code. Languages
theme light, intellij-dark (or dark), vscode-dark, auto auto Colors. auto is light, or intellij-dark when the computer is in dark mode. Themes
readonly on / off off Can't be edited, but can be selected, searched and copied. Is sent with the form. Read-only and disabled
disabled on / off off Faded out, can't be used, not sent with the form.
minify on / off off The form receives the code without line breaks, indentation and comments. The editor keeps showing it as typed. minify
width a number (pixels) or any CSS length full width Width of the editor. Size
height a number (pixels) or any CSS length grows with the code Fixed height; longer code scrolls inside the editor.
indent tab, or a number of spaces detected What Tab inserts. Without it, the editor uses whatever the code already uses.
style CSS none Styles the outer box (border, margins, max-height…) and can set the color variables.
form a form's id the form around it Sends the code with that form even when the editor isn't inside it.
aria-label any text none What screen readers call the editor, when it has no <label for>.
hidden on / off off Hides the editor, as on any HTML element. A hidden editor is still sent with its form.

On / off attributes are on whenever they're present, whatever their value. minify="false" turns minify on, just like disabled="false" on an <input>. To turn one off, leave the attribute out.

Putting code in the editor

Paste the code between the tags and indent it to match your page. The editor removes the indentation that every line shares, plus any blank lines at the start and end.

Code that contains <, HTML or XML

The browser reads everything between <code-editor> and </code-editor> as HTML before the editor sees it. Code with no tags in it (JSON, JavaScript, CSS, shell) is safe to paste. But HTML, XML, or code where < is directly followed by a letter (if (a<b)) gets changed by the browser, and any <script> or <style> in it would run.

Size

By default the editor is as wide as its container and grows with its code. Use height for a fixed height, or style="max-height: …" to let it grow up to a limit. Longer code scrolls inside the editor.

Editing and keyboard

The editor works like VS Code or IntelliJ. Shortcuts use Ctrl on Windows and Linux and Cmd on a Mac.

Keys What happens
Tab / Shift+TabIndent / outdent. With text selected, the whole lines move.
Esc, then TabLeave the editor and go to the next field (Tab alone indents)
Ctrl+click or Alt+clickAdd another cursor
Alt+dragSelect a rectangle (column selection)
Ctrl+Alt+↑ / ↓Add a cursor on the line above / below
Ctrl+DAlso select the next occurrence of the current word
Ctrl+Shift+LSelect every occurrence
Alt+↑ / ↓Move the line up / down
Shift+Alt+↑ / ↓Copy the line up / down
Ctrl+/Comment / uncomment
Ctrl+] / Ctrl+[Indent / outdent the line
Ctrl+FFind and replace. F3 / Shift+F3: next / previous match.
Ctrl+Alt+GGo to line
Ctrl+SpaceSuggestions (HTML tags, CSS properties, JavaScript names)
Ctrl+Z / Ctrl+Y or Ctrl+Shift+ZUndo / redo

Brackets and quotes close themselves, the matching bracket lights up, and the arrows next to the line numbers fold blocks of code. What Tab inserts comes from the code itself: tabs if it's indented with tabs, otherwise spaces. indent="tab" or indent="4" sets it explicitly.

Forms

Give the editor a name and it's sent with its form like any other field. You don't need any JavaScript, and it works with:

  • a normal submit: a submit button, or form.submit();
  • new FormData(form) and fetch;
  • jQuery: $(form).serialize(), $(form).serializeArray() and $.post(url, $(form).serialize()).

Good to know

  • Line breaks arrive as \r\n. Browsers send every multi-line form field that way, so ColdFusion receives \r\n in FORM.query. Tabs and spaces arrive as typed.
  • Reset brings back the code the page loaded with.
  • readonly editors are sent; disabled ones, and editors in a disabled <fieldset>, are not.
  • An editor without name or id isn't sent.

minify

With minify, the form receives the code without the whitespace that's only there for layout (line breaks, tabs, indentation) and without comments. The editor keeps showing the code as typed.

It never changes what's inside strings, template literals, regular expressions, attribute values or CDATA sections, and it keeps one space wherever two words would otherwise run together (return x stays return x).

Language What the form receives
jsonStandard compact JSON: {"a":1,"b":[1,2]}. Invalid JSON is stripped the same way, never rewritten.
javascript, typescript, jsx, tsx No whitespace or comments. A line break stays where removing it could change what the code does, for example between statements without semicolons.
cssNo whitespace or comments, except spaces that matter (.a .b, calc(1px + 2px)).
html, xmlNo whitespace between tags and no comments. Whitespace in text becomes one space (also inside <pre>). <script> and <style> follow the JavaScript and CSS rules.
textEvery run of whitespace becomes one space.
shellUnchanged: in shell scripts, line breaks and spaces separate commands and arguments.

Accessibility

			
    
				
  • Labels: a <label for="editor-id"> works as with any field:
					clicking it puts the cursor in the editor, and screen readers read it as the editor's name. Without a
					visible label, use aria-label.
    • 
				
  • Keyboard: Tab indents inside the editor, so press Esc and then
					Tab to move to the next field. In readonly editors, Tab moves on
					right away.
    • 
				
  • Focus: the editor shows a visible outline while it has focus.

Troubleshooting

			

				

					
						

							Problem
							Why, and what to do
						

					
					
						

							The code looks different from what I wrote
							The browser parsed it as HTML. Wrap it in <script type="text/plain">. See
								Putting code in. The console shows a warning when this happens.
						

						

							minify="false" still minifies
							On / off attributes are on whenever present. Leave the attribute out.
						

						

							The form doesn't send the code
							The editor needs a name (or id) and must not be
								disabled. Also check that no script replaced its content with
								.html() or .text().
						

						

							The server gets \r\n line breaks
							Normal for every multi-line form field.
						

						

							Tab doesn't go to the next field
							It indents. Press Esc first.
						

						

							The console says "unknown language" or "unknown theme"
							Check the spelling against the language and
								theme lists.
						

						

							My HTML formatter changed the code inside <code-editor>
							Formatters treat it as normal HTML text. Tell yours to leave it alone. In VS Code, add it to
								the html.format.contentUnformatted setting
								("pre,code,textarea,code-editor").
